ID: FIX-007
Tipo: Correcao
Nome: Tratamento de queda do MySQL no login

Objetivo:
Evitar fatal error no login quando o MySQL fecha ou perde a conexao durante a tentativa de autenticacao.

Contexto:
Foi identificado erro `SQLSTATE[HY000]: General error: 2006 MySQL server has gone away` em `UsuarioRepository::findByUsuario()`. O erro ocorria durante o POST de login e vazava como fatal error para a tela.

Arquivos alterados:
- app/Services/AuthService.php
- docs/features/FIX-007.md

Mudanca realizada:
- O fluxo de login passou a capturar `PDOException` ao buscar o usuario.
- A falha de banco passa a retornar erro tratado na tela de login.
- A atualizacao de `ultimo_acesso` tambem passou a ser tolerante a falha, sem bloquear login quando a credencial ja foi validada.
- As falhas tecnicas sao registradas em `storage/logs/auth-YYYY-MM.log`.

Banco de dados:
- Mudanca de schema: nao
- Mudanca de dados: nao
- Script necessario: nao

Impacto em producao:
Baixo. A mudanca afeta apenas o tratamento de erro no login.

Afeta rotas criticas:
Sim. Afeta `/login`.

Risco:
Baixo. A autenticacao continua exigindo usuario ativo e senha valida. A unica tolerancia adicionada e para falha na atualizacao do ultimo acesso depois da senha ja ter sido confirmada.

Validacao minima:
- `php -l app/Services/AuthService.php`
- `git diff --check`
- Tentar login com MySQL ativo.
- Confirmar que erro de banco nao gera fatal quando o MySQL estiver indisponivel.

Origem validada: estrategia-nerd-stage
Paridade local -> stage: nao validada
Paridade stage -> pacote: nao validada

Validado local: parcialmente
Validado stage: nao

Apto para release: nao

Observacoes:
- Esta correcao nao resolve a causa operacional da queda do MySQL. Se o erro persistir, verificar XAMPP/MySQL, logs do MySQL, `max_allowed_packet`, `wait_timeout` e disponibilidade da porta configurada em `DB_PORT`.
