# IMP-012 - Opcao de backup sem uploads

## Objetivo

Permitir que a rotina de backup sistemico gere pacotes leves sem a pasta `uploads`, mantendo a opcao de incluir midias quando o operador precisar de um backup completo.

## Contexto

Os backups recentes voltaram a ficar grandes por causa de midias em `uploads.zip`, nao por crescimento dos arquivos do sistema. A rotina anterior sempre gerava banco, uploads e sistema no mesmo backup, o que dificultava rodar backups tecnicos rapidos.

## Arquivos alterados

- `scripts/backup/BackupManager.php`
- `scripts/backup.php`
- `app/Controllers/Site/BackupToolsController.php`
- `app/Services/Site/BackupService.php`
- `app/Services/Site/DropboxBackupService.php`
- `app/Views/site/partials/backup-tools-content.php`
- `docs/features/IMP-012.md`

## Impacto em producao

Baixo. A mudanca afeta a rotina local/admin de backup. Backups antigos continuam validos. Novos backups podem ser gerados com ou sem `uploads.zip`.

## Mudanca de schema

Nao ha.

## Mudanca de dados

Nao ha mudanca em banco. O manifesto de novos backups passa a registrar `includes_uploads`.

## Dependencias

Nao ha nova dependencia.

## Risco

Medio operacional. Um backup sem uploads nao serve para recompor midias. A interface deixa essa escolha explicita e o restore passa a aplicar uploads somente quando eles existirem no backup.

## Validacao

- Validar sintaxe PHP dos arquivos alterados.
- Confirmar que a tela exibe a opcao `Incluir pasta uploads`.
- Confirmar que a verificacao aceita backup sem uploads.
- Confirmar que o envio para Dropbox ignora `uploads.zip` quando ausente.

## Resultado da validacao local

- `php -l` sem erros nos arquivos PHP alterados.
- Backup local sem uploads gerado com sucesso: `BS-LOCAL-20260513-234540`.
- Verificacao do backup `BS-LOCAL-20260513-234540`: banco OK, uploads nao incluidos, sistema OK, resultado final valido.
