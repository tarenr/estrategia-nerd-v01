ID: IMP-023
Tipo: Melhoria
Nome: Migracao do backup (sistemico e editorial) do Dropbox para o Google Drive, com automacao via CLI e tarefa agendada

Objetivo:
Consolidar o destino de nuvem do backup do Estrategia Nerd (sistemico: banco/uploads/sistema; editorial: pacotes de conteudo) no Google Drive, descontinuando o Dropbox, e tornar a rotina independente do admin (rodavel via CLI + tarefa agendada do Windows), permitindo remover as paginas de backup do menu administrativo.

Contexto:
O backup sistemico usava o Dropbox como destino de nuvem, com upload manual via botao no admin (secoes "Backup Sistemico" e "Backup em Nuvem"). Uma investigacao paralela do backup geral do Forge (the-forge, rotina restic+rclone) mostrou que:
- O perfil LOCAL do backup sistemico ja e redundante com o Forge (que faz backup e dump do MySQL local da pasta Projects).
- Os perfis STAGE e PRODUCAO nao tem equivalente no Forge, pois dependem de FTP-pull direto no Hostinger (BackupManager::run('stage'|'production')), algo que o Forge nao faz (ele so enxerga esta maquina local).
- O Forge ja possui integracao pronta (obterStatusEstrategiaNerd() em backupRoutes.js) que le os manifest.json gerados pelo BackupManager em `E:\Taren\Documents\Backup\Estrategia Nerd\{02-stage,03-prod}\{dados,tecnico}\` e exibe o status na propria pagina de Backups do Forge - nao precisou de nenhuma mudanca no lado do Forge.
- Os scripts CLI existentes (scripts/backup.php, scripts/content-sync.php) geravam backups locais mas nao tinham nenhum comando para enviar a nuvem - isso so acontecia clicando no admin.

Decisao: manter o FTP-pull de stage/producao (unica fonte real desses dados), trocar o destino de nuvem para Google Drive (mesma conta ja usada para o backup editorial, criada em IMP anterior desta sessao), adicionar um comando de CLI para o upload, orquestrar tudo via tarefa agendada do Windows, e remover as paginas de backup do menu do admin (rotas continuam existindo, so nao aparecem mais na navegacao).

Arquivos alterados:
- app/Services/Site/GoogleDriveBackupService.php (novo: uploadLatest/uploadBackup/deleteBackup para o sistemico, alem dos metodos editoriais ja existentes)
- scripts/backup.php (novo comando `upload-cloud`)
- scripts/content-sync.php (novo comando `upload-cloud`)
- scripts/backup/Invoke-DailyBackup.ps1 (novo: orquestra local/stage/producao sistemico + local/producao editorial)
- app/Controllers/Admin/OperationsV2Controller.php (dispatch google_drive_upload_editorial_package/latest/delete; remocao do embed do BackupToolsController na pagina Backup em Nuvem)
- app/Views/admin/operations-v2/backup-nuvem.php (remocao completa das referencias ao Dropbox; "Editorial" na pagina passa a refletir o Google Drive)
- app/Views/admin/operations-v2/panel.php (remocao dos 3 cards de modulo de backup da Visao Geral)
- app/Views/components/admin/sidebar.php (remocao dos 3 itens de backup do menu)

Impacto em producao: medio
- O backup de PRODUCAO foi executado de verdade (FTP-pull real + upload real ao Google Drive), confirmado no manifest.json e na propria pagina de Backups do Forge.
- Porem as mudancas de CODIGO do admin (remocao de menu, novo servico, novos comandos CLI) existem SO NO AMBIENTE LOCAL ate agora - nao foram replicadas para stage nem producao via `content-sync.php apply-code`. O admin de stage/producao ainda mostra a interface antiga (com Dropbox) ate essa publicacao acontecer, seguindo o fluxo oficial (secao 4 do CODEX-REGRAS-PERMANENTES.txt).

Afeta rotas criticas: nao (rotas publicas do site nao foram tocadas; rotas do admin `/admin/central-operacional-v2/backup-*` continuam existindo, so saem do menu)

Risco:

- Medio para o fluxo de backup: se a tarefa agendada falhar silenciosamente, backups de stage/producao podem parar de ser gerados sem aviso visivel no admin (ja que a pagina saiu do menu). Mitigacao: o log em storage/logs/daily-backup-YYYY-MM.log registra cada execucao, e o proprio Forge continua mostrando a data do ultimo backup disponivel.
