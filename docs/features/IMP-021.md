# IMP-021 - Criacao automatizada de rascunho de post (skill /post-blog)

Tipo: Melhoria
Status: Parcial (fase 1 - rascunho local)
Data: 2026-09-11

## Contexto

O portal precisa produzir posts com mais frequencia. Foi criada uma skill de IA
(Claude Code, `/post-blog`) que gera titulo, resumo, conteudo HTML (seguindo as
estruturas oficiais de `docs/blog-estruturas-de-conteudo.html`), SEO, capa e
imagens de apoio (via ComfyUI local), e insere o resultado como **rascunho no
banco local** para revisao humana no admin.

Nenhuma automacao publica em producao nesta fase. Um script separado para
publicar o post aprovado em producao (`scripts/en-blog-publish-prod.php`) esta
planejado mas nao implementado — depende de confirmar paridade de schema com o
banco de producao antes de escrever qualquer linha.

## Decisao de excecao ao fluxo padrao

O `docs/CODEX-REGRAS-PERMANENTES.txt` (secao 3) proibe gerar pacote de producao
a partir do ambiente local. Essa regra rege o **pacote de codigo/implementacao**.
Decisao do responsavel pelo projeto (Taren): para **conteudo editorial** (posts
individuais, nao codigo), o fluxo aprovado e local -> revisao humana -> escrita
direta no banco de producao (com backup obrigatorio antes), sem passar por
stage. O deploy de codigo continua exclusivamente pelo fluxo padrao
(local -> stage -> pacote -> producao). Este documento registra essa excecao
para conteudo; a fase 2 (publish-prod) vai referenciar esta decisao.

## Escopo (fase 1)

- Nova skill Claude Code em `.claude/skills/post-blog/` (fora do repo do site,
  fica no workspace `C:\Users\WINDOWS\projetos`).
- Novo script `scripts/en-blog-draft.php`: le um JSON, resolve categoria por
  slug, gera slug unico do post, copia capa/imagens para
  `public/uploads/posts/{slug}/images/`, insere o post via
  `App\Repositories\PostRepository::insertAdmin()` com `status=rascunho`.
- Nao adiciona rota HTTP nova, nao mexe em Controller/Service/View existentes.
- `E:\AI\en-image\gen.py`: adicionado ratio `blog` (1280x720, 16:9) para capa
  de post — arquivo fora do repo do site (ferramenta de geracao de imagem
  compartilhada com a skill `/post-instagram`).

- `C:\xampp\php\php.exe -l scripts\en-blog-draft.php`
- Teste manual: gerar 1 post via skill e conferir o rascunho em
  `/admin/editar-post?id=N` no ambiente local.

## Observacoes

- Sem mudanca de schema. Sem mudanca de dados existente (so insercao de posts
  novos, sempre como rascunho).
- Post so vira publicado/agendado se um humano mudar o status no admin (fase 1)
  ou aprovar explicitamente a publicacao em producao (fase 2, nao implementada).
- Fase 2 (`en-blog-publish-prod.php`) exige: teste de conexao/schema do banco de
  producao, mapeamento de categoria por slug (mesmo padrao usado no
  `ContentSyncManager::applyPosts`), backup via `scripts/backup.php run production`
  antes de qualquer escrita, e aprovacao explicita por post.
