# IMP-020 - Revisao dos graficos do dashboard antes da padronizacao geral

Tipo: Melhoria
Status: Planejado
Data: 2026-08-12

## Contexto

Antes de aplicar o novo padrao visual em todas as telas do sistema, existe uma mudanca prioritaria no dashboard: revisar os graficos. Essa etapa deve acontecer antes da padronizacao geral para evitar que o dashboard seja apenas ajustado visualmente sem resolver a organizacao real das informacoes.

O dashboard ja possui graficos implementados com Chart.js, mas a proxima revisao deve avaliar se eles continuam ajudando na leitura operacional ou se estao ocupando espaco demais, repetindo informacoes dos cards, dificultando comparacao ou quebrando o ritmo visual da tela.

## Objetivo

Reorganizar os graficos do dashboard para que eles respondam perguntas claras, ocupem espaco proporcional e sigam o padrao visual definido para o sistema antes que esse padrao seja aplicado nas demais telas.

## Decisao fechada

- Nao criar dashboards separados para mensal e anual.
- Manter a mesma tela Dashboard.
- O seletor `Mensal | Anual` deve mudar apenas:
  - periodo consultado;
  - textos dos cards e graficos;
  - agrupamento dos dados;
  - eixo X dos graficos.

## Ordem correta

1. Revisar os graficos do dashboard.
2. Ajustar a estrutura visual do dashboard com base nessa revisao.
3. Depois aplicar o padrao nas demais telas do sistema.

## Planejamento consolidado com a padronizacao geral

Esta melhoria passa a ser a etapa anterior obrigatoria antes da revisao visual completa do sistema. A padronizacao geral das telas nao deve comecar pelo restante do sistema enquanto o dashboard ainda estiver com graficos desalinhados ao periodo selecionado.

### Prioridade oficial

```text
1. Graficos do dashboard
2. Layout do dashboard
3. Padronizacao geral das telas
```

### Etapa 1 - Corrigir os graficos do dashboard

- Manter uma unica tela Dashboard.
- Usar o seletor `Mensal | Anual`.
- Fazer todos os graficos respeitarem o mesmo periodo e agrupamento.
- Corrigir principalmente:
  - `Previsto x Realizado`;
  - `Fluxo de Caixa`;
  - `Categorias`;
  - `Patrimonio`;
  - `Contas a pagar por vencimento`.
- Garantir que o eixo X respeite o periodo mesmo sem dados.

### Etapa 2 - Ajustar o layout do dashboard

- Aplicar o padrao visual novo primeiro no dashboard.
- Reduzir blocos grandes demais.
- Separar melhor cards, graficos e listas.
- Fazer `Previsto x Realizado` ficar maior e sozinho.
- Deixar os graficos secundarios em blocos menores e consistentes.
- Evitar repeticao de informacao entre card e grafico.

### Etapa 3 - Aplicar o padrao visual geral

- Aplicar somente depois do dashboard estar correto.
- Revisar todas as telas seguindo o padrao criado:
  - tamanhos padronizados;
  - cards menores em telas operacionais;
  - tabelas somente quando fizerem sentido;
  - listas compactas para historicos curtos;
  - formularios em blocos organizados;
  - campos com tamanhos consistentes;
  - campos condicionais sem buracos quando somem.

### Ordem das telas depois do dashboard

1. Lancamentos.
2. Cartoes e faturas.
3. Contas e categorias.
4. Veiculos, abastecimentos e manutencoes.
5. Central de Informacoes.
6. Investimentos.
7. Relatorios.
8. Demais cadastros.

## Graficos principais planejados

### Previsto x Realizado

- Deve ficar sozinho e maior, porque carrega muita informacao.
- Deve comparar receitas, despesas e investimentos previstos e realizados.
- Deve usar o mesmo agrupamento do modo atual.

### Fluxo de Caixa

- Deve acompanhar o mesmo periodo do dashboard.
- Nao pode continuar mostrando meses quando o modo estiver mensal ou semanal.
- Deve usar o mesmo agrupamento do `Previsto x Realizado`.

### Categorias

- Deve mostrar distribuicao ou ranking de gastos por categoria.
- Modo mensal: gastos do mes.
- Modo anual: gastos do ano ou intervalo selecionado.

### Patrimonio

- Deve mostrar composicao entre saldo em contas e investimentos.

### Contas a pagar por vencimento

- Deve agrupar pendencias por proximidade de vencimento.

### Futuro possivel

- Gastos por cartao.
- Comparacao com periodo anterior.
- Avaliar ECharts futuramente, mas manter Chart.js por enquanto.

## Regra de agrupamento

### Modo Mensal

- Agrupar por semanas de calendario.
- Primeiro grupo: dia `01` ate o primeiro domingo.
- Grupos seguintes: segunda a domingo.
- Ultimo grupo: segunda ate o ultimo dia do mes.
- Exemplo para agosto/2026:

```text
01-02
03-09
10-16
17-23
24-30
31
```

### Modo Anual sem data customizada

- Agrupar por meses.

```text
Jan, Fev, Mar...
```

### Modo Anual com data inicial/final

- Ate `45 dias`: agrupar por semanas de calendario.
- Acima de `45 dias`: agrupar por meses.

## Regra obrigatoria do eixo X

Mesmo quando nao houver dados, o eixo X deve respeitar o periodo selecionado.

Nao deve acontecer:

- dashboard mensal mostrando meses no eixo;
- dashboard anual com intervalo curto mostrando 30 dias soltos;
- grafico fixo em meses quando o usuario selecionou intervalo semanal;
- `Previsto x Realizado` e `Fluxo de Caixa` usando agrupamentos diferentes do modo atual.

## Pontos de analise

- Identificar quais graficos realmente precisam ficar no dashboard principal.
- Remover ou reduzir graficos que repetem a mesma informacao dos cards.
- Definir tamanho padrao para area de grafico.
- Evitar graficos com altura exagerada ou blocos grandes demais.
- Garantir que graficos tenham titulo, contexto e estado vazio padronizados.
- Separar indicadores principais de analises complementares.
- Avaliar se alguns graficos devem sair do dashboard e ir para relatorios ou telas internas.
- Garantir boa leitura em desktop e mobile.
- Manter filtros funcionando sem recarregar a pagina quando aplicavel.

## Regras propostas

- Dashboard deve priorizar leitura rapida.
- Grafico no dashboard precisa responder uma pergunta objetiva.
- Card mostra numero principal; grafico mostra tendencia, comparacao ou distribuicao.
- Se o grafico nao acrescentar leitura nova, ele deve ser removido, compactado ou movido.
- Grafico nao deve virar o elemento dominante da tela sem necessidade.
- Altura e largura dos blocos devem seguir uma escala padrao.
- Todos os graficos temporais do dashboard devem usar o agrupamento calculado pelo modo/periodo atual.

## Validacao esperada

- Dashboard continua carregando sem erro.
- Graficos renderizam com altura controlada.
- Estados vazios aparecem corretamente.
- Filtros continuam atualizando os dados.
- Nao ha informacao principal duplicada sem motivo.
- Eixo X respeita o modo e o periodo selecionados mesmo sem dados.
- `Previsto x Realizado` e `Fluxo de Caixa` usam o mesmo agrupamento.
- Layout fica consistente em desktop e mobile.
- A pagina continua legivel mesmo quando Chart.js falhar.
