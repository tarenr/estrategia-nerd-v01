Estruturas oficiais de conteudo do blog

Este arquivo documenta as estruturas de conteudo que o editor de posts e o front do blog aceitam hoje no projeto. O objetivo e padronizar a producao editorial, evitar HTML improvisado e registrar o formato real dos blocos que ja existem no sistema.

1) Objetivo e escopo

Esta documentacao cobre o conteudo do corpo do post, isto e, o HTML salvo em conteudo e depois tratado pelo front em App\Services\Site\PostService. Ela nao documenta layout de pagina, configuracoes SEO do formulario nem elementos do header/hero do post.

Documenta apenas o que ja existe de verdade no editor e no front.
Ideias futuras devem entrar em outra secao ou em outro arquivo, para nao misturar regra atual com experimento.

2) Estruturas permitidas

Estrutura Status Observacao
Paragrafo (<p>) Permitido Base do texto corrido do post.
Titulo de secao (<h2>) Permitido Entra no indice do post automaticamente.
Subtitulo (<h3>) Permitido Tem estilo visual proprio no tema do artigo.
Lista (<ul> / <ol>) Permitido Usar para sequencias, bullets e comparacoes simples.
Citacao (<blockquote>) Permitido Aplicada pelo botao de citacao do editor.
Link (<a>) Permitido Inserido pelo modal de link do editor.
Imagem editorial Permitido Usa figure.article-figure.content-block-image.
Video editorial Permitido Usa figure.content-block.content-block-video.
Bloco de audio editorial Permitido Usa div.en-audio-block.
Tabela HTML Permitido O front envolve a tabela em .article-table-wrap.
Blocos custom arbitrarios Evitar So usar classes que o front conhece e estiliza.

4) Midias suportadas

Aqui ficam as estruturas oficiais de imagem e video com HTML e preview renderizado.

Bloco de imagem

Padrao oficial
HTML
<figure class="article-figure content-block-image"
  data-en-block="media"
  data-media-type="image"
  data-src="uploads/posts/slug/imagens/img-001.webp"
  data-alt="Descricao curta"
  data-caption="Legenda opcional">
  <img src="uploads/posts/slug/imagens/img-001.webp" alt="Descricao curta">
  <figcaption>Legenda opcional</figcaption>
</figure>
Como vai ser exibido
Use para ilustracao, mapa, print, arte ou apoio visual. O ideal e inserir pelo editor para manter data-src, alt e legenda consistentes.

Bloco de video

Padrao oficial
HTML
<figure class="content-block content-block-video"
  data-en-block="media"
  data-media-type="video"
  data-src="https://www.youtube.com/watch?v=abc123"
  data-caption="Legenda opcional">
  <div class="content-block-label">Video</div>
  <div class="aspect-video">
    <iframe src="https://www.youtube.com/embed/abc123"
      title="Video incorporado"
      loading="lazy"
      allowfullscreen></iframe>
  </div>
  <figcaption>Legenda opcional</figcaption>
</figure>
Como vai ser exibido
Video
▶
Legenda opcional
Aceita embed do YouTube, iframe pronto ou arquivo proprio em <video>. Inserir pelo bloco oficial evita quebrar a estrutura.
Regra pratica: imagem e video devem ser inseridos pelo editor, nao colados como HTML manual sempre que houver opcao de bloco pronta.

8) Regras obrigatorias

  • Usar h2 para secoes principais que devam aparecer no indice do artigo.
  • Usar h3 apenas para subtitulos internos, sabendo que o tema aplica estilo proprio.
  • Inserir imagem, video e audio pelos blocos do editor sempre que possivel.
  • Manter figcaption apenas quando houver legenda de fato.
  • Preferir caminhos de midia dentro de uploads/posts/{slug}.
  • Respeitar os nomes curtos gerados pelo sistema para imagem, video e audio.
  • Evitar colar HTML externo cheio de estilos inline.

9) Restricoes e o que evitar

Nao tratar o conteudo do post como pagina livre. O corpo do artigo nao deve receber HTML arbitrario com dezenas de classes, estilos inline grandes ou estruturas que o front nao conhece.
Evitar Motivo
Colar blocos com CSS inline extenso Quebra consistencia visual e aumenta risco de regressao.
Criar classes novas direto no HTML do post O front pode nao estilizar ou normalizar corretamente.
Usar h3 esperando visual neutro O tema aplica destaque proprio em .article-content h3.
Salvar wrapper visual desnecessario ao redor de tabela O sistema ja adiciona o wrapper de tabela no front.
Duplicar blocos de audio antigos O padrao oficial agora e .en-audio-block.

10) Boas praticas editoriais

Hierarquia

  • H2 para macrosecoes.
  • H3 para desdobramento interno.
  • Paragrafo curto entre blocos para manter leitura fluida.

Midia

  • Legenda apenas quando agrega contexto.
  • Imagem deve ter alt objetivo.
  • Audio deve ter titulo e CTA claros.

Semantica

  • Citacao para frase destacada ou fonte.
  • Lista para comparacao ou passos.
  • Tabela quando houver dados tabulares de verdade.

Consistencia

  • Usar os blocos oficiais em todos os posts novos.
  • Evitar misturar estruturas antigas e novas no mesmo artigo.
  • Se surgir nova estrutura, documentar aqui no mesmo ciclo.

11) Checklist antes de publicar

  1. Conferir se os h2 principais estao corretos.
  2. Verificar se imagens, videos e audios foram inseridos pelos blocos oficiais.
  3. Garantir que caminhos de midia apontem para arquivos validos.
  4. Revisar se nao entrou HTML estranho de copia e cola.
  5. Testar o preview do post.
  6. Se houver novo tipo de bloco, atualizar esta documentacao antes de fechar a entrega.
